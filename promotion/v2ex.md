**标题**：开源了爬虫的「机场节点代理池」——把订阅里用不完的节点管起来，海外采集不再买昂贵代理

**正文**：

做海外数据采集的都知道，代理是最头疼的成本：

- 商业代理池按流量计费，随便采几万条数据就是几百上千块；
- 而手上机场订阅一个月几十块，动辄二三十个节点——日常只用一两个，剩下 90% 全在吃灰。

我把这份「吃灰的节点」用起来了，做成了一个开源的节点管理器，管爬虫采集场景下的所有脏活：

- **节点读取**：从 Clash 策略组拉取全部节点，自动过滤订阅元数据（"剩余流量""到期时间"）、嵌套策略组
- **双重验证**：切换前 API 测延迟 + 切换后经代理出口真实访问目标站，两个都过了才算切换成功（只信 API 的 204 会被坑）
- **负载均衡**：round_robin / random / least_403 / least_used 四种策略，按下载次数或 403 历史调度
- **失败切换**：累计 3 次 403 自动换节点；后台守护线程定时巡检，节点中途挂了也能自愈
- **按站点隔离的黑名单**：A 站封的节点不影响 B 站使用（踩过坑才知道这个多重要）
- **误杀保护**：黑名单数量接近节点总数自动清空，不会死锁

架构很简单：一个 `clash_manager.py`（单文件，无框架依赖）+ 一个 CLI + Docker 部署的 Mihomo。核心机制来自我在实际爬虫项目里的生产踩坑，跑了几个月，稳定切了几百次节点。

```python
manager = ClashManager({
    "api_url": "http://127.0.0.1:9099",
    "post_switch_test_url": "https://你的目标站/",
    "switch_strategy": "least_403",
})
proxies = manager.get_proxy_config()
resp = requests.get(url, proxies=proxies)
if resp.status_code == 403:
    manager.increment_403_error()   # 3 次自动切节点
```

适合的场景：**少量数据的海外采集**（学术文献、公开数据、新闻资讯），不适合每秒上百请求的大规模抓取（那种还是得上商业代理池）。
